## 1. 问题与目标

在浏览器、Cursor、VS Code、antigravity 等应用中,用户需批量发送多条文本。工具通过"点击输入点→粘贴→点击发送→冷却→ROI变化判定"流程自动化发送,完全依赖屏幕ROI变化检测推进(不读取应用内部状态)。

**核心约束**:目标窗口运行期间不移动/缩放/滚动;每次运行重新标定(代码中未发现任何标定持久化/配置加载逻辑，确认该约束仍成立)。

**成功指标**:
- 2分钟内完成标定并成功运行
- ROI变化满足条件后自动推进,Pause/Resume/Stop正确执行
- 连续运行30分钟无崩溃,CPU稳定(1 FPS采样)

---

## 2. 平台与假设

**平台**: Windows、macOS(仅单显示器)
**目标应用**: 浏览器、Cursor、VS Code、antigravity(作为被操作窗口,不做集成)

**非目标**:
- 不支持运行中跟踪窗口位置变化
- 不做视觉/控件自动识别
- 不支持超时自动失败(无限等待,靠Pause/Stop控制)
- 不支持应用内部注入/读取DOM

## 3. UI与交互

### 3.1 运行面板(小窗)
- Always on top
- Start后吸附到**发送按钮坐标所在屏幕**（用 `availableGeometry()` 判定）右下角，边距固定 `PANEL_MARGIN_PX=12` 逻辑像素（验收容差 ±2px，非运行时抖动）；若发送点不落在任何已知屏幕内，回退吸附到主屏幕（v1.1 未提及的兜底行为）
- Start后倒计时2秒,再执行自动化
- 显示: 进度i/N(1-based,例如1/5)、状态(Idle/Countdown/Sending/Cooling/WaitingHold/Paused)、Pause/Resume/Stop、日志(环形缓冲 `LOG_BUFFER_SIZE=200` 条)
- 固定黄色提示条,精确文案："⚠️ 运行中请勿操作目标窗口"；只要状态不是 Idle（即 Countdown/Sending/Cooling/WaitingHold/Paused 均含）就显示,Stop（回到Idle）后隐藏
- 校准按钮在对应坐标已设置后变为绿色高亮(`#d4edda`)，作为完成度的视觉提示
- **未决问题**：阈值输入框在 Paused 状态下当前被禁用；代码注释显示这与早期设计意图（Paused 时应可编辑）存在矛盾，尚未解决，产品需明确最终行为

### 3.2 标定面板(每次运行必须)
- ROI: 矩形/圆形(圆形由拖拽矩形生成内切圆:cx=x+w/2, cy=y+h/2, r=min(w,h)/2)
- 输入位置: 点击点(抢焦点)
- 发送按钮: 点击点
- ROI允许与发送按钮重合(无几何碰撞校验，属于"未禁止即允许"，非显式设计校验)
- 框选/取点过程中支持实时十字准星与坐标读数显示；支持 ESC 取消、Enter 确认快捷键(v1.1 未记录)

### 3.3 阈值校准
- 触发: 用户手动点击"校准"或冷却后高亮提示(非强制)
- 默认采集 `CALIB_FRAMES_DEFAULT=8` 帧(可调节范围 `CALIB_FRAMES_MIN=5` ~ `CALIB_FRAMES_MAX=10`)，帧间隔 `CALIB_INTERVAL_MS=150ms`，首帧作为参考帧
- 推荐值算法：对采样帧两两求 diff 得到 μ(均值)、σ(标准差)，推荐阈值 `TH_rec = clamp(μ + 3σ, TH_HOLD_MIN=0.005, TH_HOLD_MAX=0.2)`；若原始值超过上限，提示"噪声异常,建议重新选择ROI"
- 默认未校准前TH_HOLD=0.02(即 `TH_HOLD_DEFAULT`)

## 4. 消息与流程

### 4.1 消息输入
- 列表模式: 一条消息一个条目,条目支持多行(原生 QTextEdit 换行透传)
- Enter=换行(不发送)
- 列表尾部自动保持空条目(最后条目非空时自动追加)
- 每个条目附带删除按钮("×")；工具栏提供"清空全部"、"+ 添加消息"，并显示当前消息条数(v1.1 未记录的界面细节)
- 编辑框内按 Esc 结束编辑并失焦
- Start时过滤空条目(strip 后为空即丢弃)生成有效消息列表并锁定N,运行期间不重新过滤
- 粘贴支持多行并保留换行

### 4.2 自动化流程(每条消息)
对第i条消息:
1. 点击输入位置
2. 粘贴消息i(保留换行)
3. 单击发送按钮
4. 冷却1秒
5. 冷却结束抓取ROI帧作为参考frame_t0(每条消息重置)
6. 每秒采样1次,计算diff(frame_t, frame_t0)
7. 若diff≥TH_HOLD连续命中2次(约2秒保持改变)→判定通过,进入下一条i+1
8. 若未满足,持续等待(无限等待;靠Pause/Stop控制)

**发送成功/失败判定**: 完全依赖ROI变化,ROI选取必须与"发送后状态变化"强相关。

## 5. 变化检测

### 5.1 diff定义
- ROI转灰度(BT.601 加权：R×0.299 + G×0.587 + B×0.114)
- 差异度: d = mean(abs(frame_t - frame_t0)) / 255.0, 范围[0,1]
- 圆形ROI: 仅统计圆内像素(mask,基于 (x-cx)²+(y-cy)²≤r² 判定)

### 5.2 "保持2秒"口径
- 1 FPS下连续2次命中即通过(`HOLD_HITS_REQUIRED=2`)
- 若diff<TH_HOLD, hold_hits归零重新计数

## 6. 多显示器与平台能力

### 6.1 坐标与截图
- 坐标: 虚拟桌面绝对坐标记录ROI、输入点、发送点
- 虚拟桌面信息获取存在三级回退：优先 mss 的 `monitors[0]`，失败则用 Qt `virtualGeometry()`，仍失败则使用硬编码 1920×1080 兜底(v1.1 未记录)
- **截图方式（已更正）**：自动化热循环中直接截取ROI区域本身(`capture_roi_gray`)，**不是**全虚拟桌面截图后裁剪——这是性能优化后的实际实现；全桌面截图函数(`capture_full_desktop`)仍存在，但仅用于校准预览等辅助场景
- 截图失败重试：`CAPTURE_RETRY_N=3` 次，间隔 `CAPTURE_RETRY_INTERVAL_MS=500ms`

### 6.2 Windows
- Per-Monitor DPI aware,避免缩放偏移
- Qt初始化前调用`SetProcessDpiAwarenessContext`（PER_MONITOR_AWARE_V2）
- 若该 API 在系统上不存在(如较旧 Windows 版本)，回退调用 Win8.1 API `SetProcessDpiAwareness(2)`(v1.1 未记录的兼容路径)
- "已设置过"判定：`GetLastError()==ERROR_ACCESS_DENIED` 视为已生效，不算失败
- 若真正失败,显示警告横幅:"⚠️ DPI感知设置失败,坐标可能偏移。建议在100%缩放下运行或重启应用"

### 6.3 macOS
- 需屏幕录制(`CGPreflightScreenCaptureAccess`)与辅助功能(`AXIsProcessTrustedWithOptions`)权限;UI启动自检并提示
- 引导文案："需要授权: {缺失项}\n\n请前往: 系统设置 → 隐私与安全性 → {缺失项}\n找到本应用并勾选启用。\n\n授权后可能需要重启应用。"
- **风险**：若运行环境未安装 `pyobjc`，权限检查会直接判定"全部通过"而非报错阻塞——这是静默假设而非真实校验，见第10节
- **仅支持单显示器环境**,多显示器暂不支持(通过独立的显示器数量检查实现，与权限检查分离)

## 7. 控制逻辑

**Pause**: 冻结当前状态、计数器、frame_t0与消息列表快照
**Resume**: 检测消息列表是否变化(对比暂停时快照，`has_changed()`);未变化继续使用同一frame_t0与计数器;已变化则停止并提示"检测到消息列表已修改,自动化已停止,请重新Start"
**Stop**: 立即停止,回到Idle

---

## 8. 边界条件与异常

### 8.1 权限与系统能力
- macOS未授权屏幕录制/辅助功能: 禁止Start并提示开启路径(但受6.3所述 pyobjc 缺失风险影响)
- Windows DPI设置失败: 显示可关闭警告横幅

### 8.2 运行期异常
- 截图失败: 自动重试3次(间隔500ms);仍失败弹出模态对话框,标题"无法获取屏幕截图",内容含可能原因与建议,按钮"重试"/"查看日志"/"关闭"(回Idle)
- 坐标越界(点/ROI在虚拟桌面外): 禁止Start并提示重新标定
- 剪贴板粘贴失败: 记录日志并继续(依赖ROI变化判定)；粘贴/点击操作内部异常目前会向上抛出而非静默吞掉，可能中断自动化循环(v1.1 未记录的实现细节，建议关注)
- 目标窗口失焦/被遮挡: 不强制干预,提醒用户不操作;若ROI变化异常导致无限等待,用户可Pause/Stop

### 8.3 应用级健壮性(v1.1 未记录，代码新增)
- 主线程与工作线程均安装全局异常兜底(打印完整堆栈到 stderr)，并启用 `faulthandler` 捕获底层 segfault，避免无提示崩溃
- 当前控制台日志级别被强制设为 DEBUG(无用户可调层级)，属开发期遗留配置，正式发布前应评估是否需要收敛

## 9. 验收标准

1. Always on top;Start后吸附到发送按钮所在屏幕右下角(边距12px，验收容差±2px),Countdown倒计时2秒后切换到Sending;黄色提示条"⚠️ 运行中请勿操作目标窗口"在非Idle状态(含Paused)显示、Idle隐藏
2. 每次运行必须完成ROI/输入点/发送点标定;ROI支持矩形与圆形(圆形为内切圆,diff仅统计圆内);ROI允许与发送点重合
3. 列表模式:条目支持多行,Enter换行,尾部空条目自动补,Start时过滤空条目并锁定N,支持多行粘贴保留换行
4. 每条消息: 点击输入点→粘贴→点击发送→冷却1秒→采集frame_t0→1 FPS采样diff; diff≥TH_HOLD连续命中2次推进,中断后hold_hits归零;未满足可无限等待
5. Pause冻结状态/计数器/frame_t0/消息列表快照;Resume检测消息变化,未变化沿用frame_t0,已变化停止并提示;Stop立即回Idle
6. 校准默认采集8帧(5-10可调)给出TH_HOLD推荐值(clamp(μ+3σ, 0.005, 0.2))并可微调;未校准前TH_HOLD=0.02
7. Windows: Per-Monitor DPI aware(含旧版API回退),设置失败显示警告横幅
8. macOS: 权限自检(pyobjc缺失时的假通过风险需产品确认是否接受),未授权禁用Start;仅支持单显示器
9. 截图性能路径：热循环直接截取ROI区域而非全桌面裁剪，30分钟连续运行CPU稳定

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| ROI选择不当导致误判/漏判 | UI提示"ROI应与发送后状态变化强相关";提供校准与手动微调 |
| 多显示器+DPI引发坐标偏移 | Windows强制Per-Monitor DPI aware(含旧API回退),失败显示警告;提供重新标定 |
| macOS权限导致不可用 | 启动自检、清晰引导,未授权禁用Start;仅支持单显示器 |
| **macOS 缺失 pyobjc 时权限检查静默"假通过"** | 需产品决策：是否应改为阻塞启动并提示安装依赖，而非放行(当前代码行为存在误判风险) |
| 无限等待导致误以为卡死 | 状态明确显示WaitingHold;日志显示diff/hold_hits;Pause/Stop可用 |
| 生产代码路径仍在写本地调试日志(`capture.py`/`os_adapter/__init__.py` 每次截图写 `.cursor/debug.log`) | 属技术债，非隐私泄露(不出本机)，但有IO/性能开销，建议发布前移除或加开关 |
| Paused 状态下阈值输入框是否可编辑存在未解决的设计矛盾 | 需产品明确期望行为并同步代码 |
| 点击/粘贴内部异常直接抛出而非降级处理 | 建议评估是否应捕获并记录日志后继续，而非中断整个自动化循环 |

## 附录: 核心术语

- **ROI**: Region of Interest,屏幕上检测变化的区域
- **frame_t0**: 每条消息发送后、冷却结束时采集的参考帧
- **TH_HOLD**: 变化判定阈值;diff连续命中2次即通过
- **虚拟桌面**: 多显示器合成的统一坐标空间(Windows支持多屏;macOS本版本仅支持单屏)
- **i/N**: 当前消息索引/总有效消息数(i为1-based显示,如1/5表示第一条消息)
